# Plan: Fix Auth Registration Failure (Customer/Vendor)

## Context
User reports that registering with the customer role fails. The project is a Next.js static-export app with Capacitor, Supabase for auth/database, and Drizzle ORM. Supabase already has tables and RLS policies deployed. A database trigger (`handle_new_user` on `auth.users`) exists to auto-create a row in `public.users` after signup.

## Root Cause Diagnosis
1. `app/(auth)/register/page.tsx` calls `supabase.auth.signUp({ email, password })` **without** passing `options.data` containing `full_name` and `role`.
2. The Supabase trigger `on_auth_user_created` tries to insert into `public.users` using `new.raw_user_meta_data->>'full_name'` and `new.raw_user_meta_data->>'role'`.
3. Because metadata is missing, the trigger attempts to insert `NULL` into `full_name`, which violates the `NOT NULL` constraint in the `users` table.
4. This causes the trigger to error, rolling back the `auth.users` INSERT transaction, so the entire `signUp` call fails.
5. Additionally, if the trigger were removed, the frontend attempts a manual `insert` into `users` which can race/conflict with the trigger.

## Goals
- Ensure `signUp` succeeds and correctly populates the `public.users` profile row.
- Make the registration flow robust whether the trigger is present or not.
- Wire up the login page to actually authenticate via Supabase.

## Implementation Steps

### Step 1: Fix Register Page (`app/(auth)/register/page.tsx`)
- Update the `supabase.auth.signUp()` call to include `options.data`:
  ```ts
  await supabase.auth.signUp({
    email: formData.email,
    password: formData.password,
    options: {
      data: {
        full_name: formData.fullName,
        role: role,
      },
    },
  });
  ```
- Remove the unconditional manual `supabase.from('users').insert(...)`.
- Add a robust fallback: after `signUp`, wait briefly or query `public.users` for the new `id`. If the row exists, proceed. If not (e.g., trigger not active), perform the manual insert as fallback.
- Ensure loading and error states are handled cleanly.

### Step 2: Fix Login Page (`app/(auth)/login/page.tsx`)
- Replace the stub `handleSubmit` with a real `supabase.auth.signInWithPassword({ email, password })` call.
- Add loading and error states.
- On success, the `AuthProvider` and `AuthGuard` will handle redirect automatically based on role.

### Step 3: Verify Redirects & AuthGuard
- Confirm that after successful registration/login, `AuthGuard` redirects customers to `/customer/home` and vendors to `/vendor/dashboard`.
- Ensure `AuthProvider` fetches the profile correctly (it already does, but verify it handles the new metadata-based insertion).

### Step 4: Quick Validation
- Ensure `lib/supabase.ts` client is correctly initialized with the environment variables.
- Check for any TypeScript errors after changing the registration logic.

## Success Criteria
- [ ] User can register as `customer` without errors.
- [ ] User can register as `vendor` without errors.
- [ ] After registration, `public.users` row is created with correct `full_name`, `email`, and `role`.
- [ ] User can log in with the newly created credentials.
- [ ] After login, role-based redirect works.
